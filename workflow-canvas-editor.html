The interaction, step by step

1
Drag a Device from the left palette onto the canvas. It drops in as a white Task node with one port per Channel.
2
Drag an Item Feed from the second palette — an existing one, or "+ New Feed" to define one inline. It drops in as its own navy node (try the one above). The same Feed can be dragged in more than once as separate instances.
3
Draw a Feed Link by dragging from a Feed node's output to a Task Channel's input (the navy edge above, click it to set the firing interval) — a Channel can take any number of Feed Links and Flow Links at once, from the same Feed or different ones.
4
Draw a Flow Link by dragging from a Task's output port to another Task's input port. The edge appears immediately with default delay 0–0s and no filter (implicit else) — refine it next.
5
Click any edge's label chip to open its config panel (try one above): a Feed Link gets a firing interval, a Flow Link gets a delay range and, when a Task has more than one outgoing edge, a GTIN/category filter — exactly one edge per Task is allowed to stay the catch-all "else".
6
Run starts the simulation: each Feed Link fires on its own interval, items cross Flow Links after their delay, and a read event is generated at each Channel along the way (local simulation for now — no live POST /reads yet).
Recommended library for the real build: @xyflow/react (React Flow, MIT-licensed) — it natively supports custom node components (for the port layout above), custom edge components (for the clickable delay/filter chip), and drag-to-connect between named handles, which maps directly onto Channels-as-ports rather than a generic single-handle node.
